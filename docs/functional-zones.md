# 功能区约束闭合

当前默认流程：原图 → 同一次建筑观察给出 functionalZones、墙/门/窗/比例 → 冻结观察 → 家具语意/位置 → 确定性空间约束 → 冻结最终建筑 → 装配 → 原生编辑器/漫游。没有第三轮 LLM。

`source-architecture-v1` 兼容扩展了可选 functionalZones，详见 Skill 的 architecture-pass.md。当前提示要求输出；无此字段的旧输入走兼容路径，不能声称测试了新方法。功能区包含语意、室内/阳台/室外属性、内部点和带构件类别证据的近似闭合轮廓。原始观察与家具点始终不变。

程序只复用原生房间面。闭合与通行分别计算：多个独立功能区可以通过无扇通口保持连通；功能区包含家具不等于其分隔正确。阳台无论有无家具都要成为独立逻辑闭合区域，边界可由移门/窗、围栏或空气边界组成。

- 实体墙和窗基线继续由单次建筑观察提供，不从近似功能轮廓虚构实体墙。
- 有端点依据的 passage 补逻辑宿主基线，装配为 opening 无门扇通口。既有门洞的范围优先，不能被功能轮廓扩大；窗不能转换成通口。
- railing 使用低矮原生墙，初始 110cm 是可调产品默认值。
- air 是沿明确阳台/室外空间范围建立的不可见碰撞边界。它参与原生闭合和地板推导，在 2D 以虚线显示，3D 不生成墙体网格。它不会将窗变成门，也不会封堵已有通口。
- 共用边界只存一份，程序仅加入未覆盖的区间。
- 程序尝试有实际墙线支持的局部端点延伸，最大 9 原图像素，接受条件包括功能区独立闭合数量增加、既有闭合区/家具包含/开口保留。单次可比较两个连接的组合，最多 64 次试验；不会通过反复小步移动越过原始端点边界。
- 曲线 air/railing/passage 沿原生二次路径补入未覆盖区间，保留子段控制点；共享边允许反向或部分覆盖，需双向位置与切向一致。靠近但不重合的曲线保留歧义，不合并阳台内外缘，不把弧线改成直线。未知边和没有端点依据的通口仍待复核。近似轮廓与原生面积只作宽容的一致性约束，不能作为源图几何真值。

`functional-zone-review.json` 保留各阶段原生区域分配、逻辑边界增量、通口宿主、成功/拒绝的连接与未解决区域。标准化草稿只保存功能标签的种子点，所有实际多边形仍由原生墙网推导。厘米换算、用户单墙长标定对标签点也使用同一平面比例；竖向高度独立。

中线自动校正仍关闭。历史生成 JSON 或模型不得手改；观察错误应重开原图执行，算法修复应记录新的程序派生产物，不能伪称为新一轮视觉观察。

曲线门窗的平面绘制、点击和范围使用原生墙路径上的物理距离区间。窗框及玻璃符号随路径弯曲；门洞和门框沿曲线，铰接门扇保持连接两端门框的刚性形状。3D/碰撞与平面绘制共用区间端点的数值容差，避免单位换算留下极小但全厚度的阻挡条。详见[曲线边界与开口](curved-boundaries-and-openings.md)。

## 验证中的两项表示修正

功能区种子“各占一个闭合面”仍不足以证明边界正确。当前 resolvedZoneCount 还要求已声明边界得到墙网支持，未知边继续待定；uniqueClosedZoneCount 单独保留，不能混为正确率。边界支持使用原生曲线分段及局部区间覆盖，容忍 3px 源图定位误差。程序可比较两个共同必要的连接；延伸某根墙形成 T 形交汇时保留非共线邻墙的原始位置，不拖动整组墙角。多目标同等收益且冲突时保留歧义。

功能区分隔可能把连续幕墙宿主切成多个原生段。当前仅允许 window 沿唯一、连续、方向一致的同一 sourceWallMap 基线拆成原生窗构件，保留整段投影范围及组合审计；不跨空隙、不混接相邻平行墙、不自动拆单/双扇门。原始窗观察仍完整保存在冻结源数据。该表示修正并不证明源图玻璃构造判断正确。
