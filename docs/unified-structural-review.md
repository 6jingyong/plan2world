本阶段先统一候选验收，尚未把多假设前移到第一次建筑观察，也未接入桌面额外模型调用。

新增显式 `unified-structure` scope，请求版本 `source-visual-feedback-v4`。
默认仍为建筑、家具两次观察；旧 v1/v2/v3 指导文本、请求与采用策略保留。
可选 API 与 `tooling/plan2world-visual-feedback.mjs` 共用同一入口。

- 原生编译结果在一次评估中复用；家具支撑、精确门/阻挡所有权、开口保留和用途约束
  对每个候选一起运行，不取决于本次是哪类问题触发裁片。
- 复用闭合算法的用途检查：已闭合锚点、未被墙覆盖的点、功能分隔、已证实通行与入口
  净空。允许增加分隔，保留原有分隔与正向通行证据。没有证实路径不等于不可达；
  这不是完整路径搜索，不能据此补门。
- 未明确修订的开口须保留种类、总宽度和已证实净空；链窗按精确源所有权合计。
  墙可分段/合并，不要求保留原生墙 ID。家具修订仍仅限固定的支撑冲突源记录，
  原始观察、撤回记录与原序号均保留。
- 新的源点无支撑、门冲突、丢失闭合/通行/开口，或检查/所有权/注册不完整，都会阻止
  自动采用。候选和原因保留；原有待审可以继续存在，不以报警数选择答案。
- 默认整扇推拉方案下的纯运动冲突单列程序假设；闭合门扇冲突仍可提出源问题。
  被上游阻断、合同或无法定位的结果留在审计，不逐条消耗视觉复查名额。

一批最多三个局部、三个候选、24 条上下文源记录。普通/结构问句臂的图像、记录、
锚点相同。模型请求只带本地问题、固定记录和简洁检查状态；完整检查矩阵及原生 ID
留在审计。源路径与逻辑事实摘要参与请求 hash，不用随机房间/楼层 ID 绑定请求。
CLI 输出 hash 绑定的 `baseline.structural-review.json`、`structural-review.json` 与原有
运动说明；未采用候选时，当前工程仍是基线。
