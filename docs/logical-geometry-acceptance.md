# 共享几何约束与开口墙带（P24，2026-11-01）

本轮重点是阻止程序候选引入新问题。建筑和家具仍各观察一次；不改原图、源观察、
冻结阶段或旧工程，不自动调整门宽、位置、摆向和入口。

## 共享验收

`logicalGeometryConstraints`由近墙合并、家具引导闭合、功能区闭合共同使用。
逐个保留已解析开口的身份、类型和宽度，检查实际原生片段上的重叠，包括连续窗的
后续片段；保护家具及非reject用途种子、已有闭合和功能分隔、门洞净宽与通行关系。
有源墙支撑的端点补接允许形成新的功能分隔，不能合并原来分开的闭合空间。

门检查直接复用运行时编译器的墙体和显式门扇盒体，无须先成功编译地面。
禁止新增门/墙或门/关闭门的关闭相交、采样运动阻挡；未支持、预算耗尽或无效开口
保持未完成，候选不自动接受。墙经过拆分/合并后，用源墙映射比较阻挡身份。
已有冲突继续保留，不要求静默修好后才允许保存作者工程。

通行指标是门图和直接净空线段检查，不是完整路径搜索或引擎实走。不能仅因两个点
同属一个推导房间，就断言玩家能穿过未闭合的窄缝；入口可达也检查到门侧的净空。
运动仍按1°/1cm采样、250,000盒对，不覆盖连续扫掠、家具、柱或多门同时运动。

## 已确认边界与程序补接

已接受的源passage/railing/air跨度继续按原合同应用；共享比较记录可选
`boundaryConstraintFinding`，不以删除已确认边界的方式掩盖机械冲突。
这些标记属于程序审计，实际当前门冲突仍由Godot的Checks独立显示。
算法新尝试的补接和近墙合并则必须通过上述约束，否则保留原几何及拒绝原因。

一个中间版本曾因边界冲突撤回整组已确认跨度，十图对照发现YJ215丢失闭合区域并
从可编译变成拒绝，另一张图也丢失区域。已撤销该做法，失败对照和打包版本保留。
阳台控制例也保留原600cm滑门的额外阻挡结果；有效300cm门控制独立验证正常闭合，
没有把原失败改写为成功。

## 有限厚墙内的窗口

默认宿主解析新增明确solid `thicknessPx`墙带的有限区间容纳。整个平行窗段必须在
实体外沿及端点范围内，保留其宽度和真实投影残差。不扩墙、不裁窗，不用默认墙厚
扩大近线容差。普通细墙、air/railing、斜交窗和明确指定的投影容差保持原规则。
门继续采用原单宿主规则，不借连续窗逻辑拆门。

唯一原始基线被接点拆开时，可连续覆盖多个窗片段；中间有缺口、两个墙带成立或
单宿主与另一条连续链同时成立时仍待审。已有Project/runtime格式不变，源模型不能
提交程序专用的`thicknessPx`。

Peale北侧六窗仍未解决：当前程序几何没有足够的明确墙带容纳这些偏离基线的点。
本轮不据此扩大默认墙厚，也不把只读像素候选当成生产几何。住宅原四门仍受阻。
