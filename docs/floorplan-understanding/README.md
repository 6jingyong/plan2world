# 平面图理解：条件分类与空间一致性检查

这份目录归纳用户提供的五张原始图。分类来自原图目视观察，仅用于描述适用条件与例外；它不是墙线、房间数或家具点位的标准答案。条件可以同时成立，不能将一个户型归成单一图源类型。没有记载的条件表示“尚未确认”，不等于不存在。

原始文件身份、分类词表与每图证据见 `source-profiles.json`。证据框是原图像素坐标 `[x0,y0,x1,y1]`，只用于定位说明，不参与墙线提取、闭合、吸附或建模。五张图都未形成独立的完整几何真值；不能据此报告提取准确率。

## 基本区分

1. **表示方式**：墙、框、柜、文字和阴影的画法。黑粗线、白色细框都可能表示建筑边界；图源分类不决定某根线的语义。
2. **几何与范围**：正交、斜线、弧线、凹口、独立隔断、附属图。先明确是在复原哪一个平面范围，不能把外部楼梯、小区总图、尺寸线纳入户内墙网。
3. **空间拓扑**：边界是否闭合、是否分隔正确、两侧是否相邻，是不同问题。房间由原生墙网推导；功能名称不是必须独立的房间。
4. **可通行性**：门/移门/无扇通口支持通行关系；窗表示边界上的玻璃构件，初始贯穿高度不会将窗变为可通行门。门的通行还取决于开闭状态、宽度和碰撞，这份检查不作路线验收。
5. **使用线索**：室内家具支持存在封闭空间的先验；阳台家具、开敞空间、错位观测均是例外。空房也可以是室内。家具聚类不能单独决定墙或房间数。
6. **比例与物理尺寸**：同一比例作用于两个平面坐标轴，用户给一个真实墙长后统一换算。户型面积、常见门宽和印刷比例不能直接证明缩放后图片的绝对尺寸。高度和窗台独立于平面比例。
7. **不确定性**：图上看不清、观测遗漏、程序计算错误须分别记录。建筑常识只能提醒复核，不能授权补墙、补门、移动家具。

## 功能区与通行区

这里采用用户所说的“通行区”：一组能够互相到达的空间，不仅指走廊。
一个通行连通分量可以包含多个功能区；这不是对面积或区域数量的统一
大小关系。物理上的可通行还受门的开闭状态、开口宽度和碰撞影响。

衣帽间可以在功能上独立，并经无门扇通口与卧室连通。其功能边界由
已观察的墙线与入口处的逻辑基线共同闭合；建模时该入口使用已有的
`door.type: "opening"`，不添加门扇，洞口保持可通行。已有原生房间
推导按宿主基线判断闭合，门窗渲染/碰撞按开口处理；落地窗不会因此
变成通口。

“有家具的闭合区域”是功能区候选，不能唯一确定其边界。逻辑入口的
位置与跨度需要可见开口、门框或隔断端点等依据。无依据的开放客餐区
可以先保留功能划分不确定，不能按每个家具簇补一条实体墙或自动加门。
实际墙线、逻辑入口基线与通行关系应分别保留证据，不能把推导出的入口
冒充原图上已观察到的门。

当前生成器已经支持观测到的无扇通口，P02 也已将它们计作入口。
当前 functionalZones 路径已实现基于显式功能边界证据补齐逻辑通口、围栏和空气边界，并以原生功能区分隔收益选择局部墙端连接。详见 `../functional-zones.md`。阳台也必须逻辑闭合；旧冻结结果不会被覆盖。

## 可执行规则

| 规则 | 约束 | 处理 |
| --- | --- | --- |
| H01 | 最终墙/门/窗与冻结建筑结构完全相同 | 不一致为程序冲突 |
| H02 | 原生闭合面每一边在原生墙路径上连续有依据 | 区间合并检查，允许原生 5cm/轴连接容差；显式 floorAreas 不强制围墙 |
| H03 | 已接受门窗都装配成功，宿主存在、区间有限且正长 | 不满足为程序冲突；匹配成功不代表提取语义正确 |
| H04 | 原图→cm 与相对坐标都保持平面等比例 | 不一致为程序冲突；不保证真实尺寸正确 |
| H05 | 冻结家具语意/位置在装配后保持一致 | 不一致为程序冲突 |
| P01 | 家具位于原生闭合区域 | 不满足仅复核；满足也不保证内部隔断正确 |
| P02 | 有家具的闭合区域有已有门/通口关联 | 无入口仅复核，可能是衣柜/设备井等；不增门 |
| P03 | 带门扇的门两侧预期提供有意义的空间分隔 | 在同一面内仅复核，独立隔断可例外；同面无扇通口只记上下文；不增墙 |
| P04 | 近接但未相连的墙端点可能有拓扑问题 | 按无向端点对合并重复记录；不放宽吸附半径 |
| E01 | 不确定的原始墙线/门窗候选仍须保留 | 列出候选与证据，不转为接受 |
| E02 | 平面真实尺度仍需证据 | 暂估门宽提示待标定；已有尺寸证据仍不等于外部核验 |
| U01–03 | 功能标签、立面高度、整体图像忠实度 | 缺少独立证据时明确“不可评估” |

H 是程序自洽约束，P 是可被反例推翻的建筑先验，E 是证据状态，U 是目前不可自动评估项。没有综合成功分数。所有指标必须保留各自分母，不能把“117/117 家具在闭合面内”解释为“所有房间正确”。

P03 在门中心两侧各取 **2 原图像素**的点，查询已有原生多边形及其洞。它不创建第二套房间图，也不使用身体大小或路线采样。带门扇的门两侧落在同一面可能提示隔断失效，也可能是合法独立隔断，需要原图判断；无扇通口允许属于同一开放空间，不单独触发复核。P02 使用原生面的墙 ID 与门宿主关联，不保证门宽、开闭及身体碰撞下可通过。

## 执行

```bash
node tooling/review-plan2world-conditions.mjs \
  --stage <已冻结的 architecture-stage.json> \
  --draft <对应 draft.json> \
  --source <原始图片.jpg> \
  --output <全新的诊断目录>
```

入口先在内存里调用既有确定性装配程序校验冻结阶段及最终草稿，随后读取原生房间几何进行诊断。原图只用于身份校验和报告关联；图源分类不进入算法。记录输入和程序 SHA256，写独立诊断 JSON；拒绝覆盖旧目录，不保存替代墙线或草稿。

本目录的条件诊断命令自身不进行新一轮视觉提取，也不增加 LLM 调用；它只读已冻结的观察与几何，不修改生成结果。中线校正保持关闭。当前默认生成已采用功能区约束的逻辑闭合，仍保留建筑/功能区与家具两个观测阶段，详见[功能区流程](../functional-zones.md)。

## 五图的重点反例

- 图 1：阳台有家具；厨房/餐厅/客厅等可共享外部包络。带家具不必有独立四面墙。
- 图 2：斜向玻璃幕墙、门厅曲线、多出入口和外部附属图混合；玻璃边界、房间分隔、户内范围要分别验证。印刷“Not to Scale”不能直接当像素比例尺。
- 图 3：弧形外墙与阳台边界并列，客厅内有自由端弧形隔断。不能统一拉直、强行接上每个墙端点或把虚线栏杆当落地墙。
- 图 4：黑底白色细线，带暗门/移门和圆形家具。背景极性、门的表达和家具轮廓不能套用彩色营销图的画法；有房名的区域可能没有画家具。
- 图 5：深凹户型与大面积空房、中央水印。外部凹口不能补成室内，空房不能当室外；看不清的水印交汇处不能用闭合常识掩盖。

这五张图用于扩大规则的反例覆盖，不能据此声称覆盖所有制图习惯或形成建筑专业规范。
