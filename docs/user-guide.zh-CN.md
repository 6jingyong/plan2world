# Plan2World 使用说明书

平面图 → AI 观察 → 程序重建 → 原生 Project → 编译 → Godot 漫游与家具布置。本文的“小程序”指 **Godot 独立桌面工具**，不是微信小程序。

## 选择使用方式

| 入口 | AI 账户与额度 | 使用过程 |
| --- | --- | --- |
| 插件 / Skill | 使用 AI 宿主中登录的账户，由宿主管理额度 | 在支持 Skill、图像及本仓库工具的宿主中重建；检查草稿并保存 Project，再交给 Godot |
| 独立桌面工具 | 授权 OpenRouter，或连接自己的 OpenRouter API Key | 原生界面选择原图、生成、审查、选择大门，再直接布置和漫游 |

两条入口保存相同的原生 Project，使用相同的确定性重建和编译逻辑。已有 Project 或场景可以直接打开，**漫游、视角切换、家具布置、保存和导出不消耗 AI 额度**。

## 开始前准备

- 原始 PNG、JPEG、WebP 平面图，不超过 12 MB、解码后不超过 2,400 万像素。尽量保留尺寸标注，不要用重画或拉伸后的图片代替原图。
- 图上缺少尺寸时准备一条已知实际尺寸，例如“下方外墙长 600 cm”。缺少可靠尺度时，结果只是待核对的估计。
- 完整解压 Windows 或 Linux 播放器，运行 `Plan2World.exe` 或 `Plan2World.x86_64`。保留可执行文件、`Plan2World.pck` 和整个 `core/` 文件夹；无需另装 Godot 或 Node.js。
- 默认 Forward+，旧显卡可加 `--rendering-method gl_compatibility` 启动。Windows 包尚未签名，设备兼容性仍需实际验收。

## 用法一：插件 / Skill

仓库提供可移植的 [`reconstruct-plan2world` Skill](../skills/reconstruct-plan2world/SKILL.md)，并非已经上架的独立插件商品。安装和登录由宿主管理；宿主必须能读取原图、访问本仓库并运行确定性工具。单独粘贴提示词不能替代程序校验与编译。

1. 在宿主登录你的 AI 账户，并按宿主方式加载 `skills/reconstruct-plan2world/`。例如在带本仓库的 Codex 工作区使用该 Skill；已经安装 Skill 的 ChatGPT 环境使用既有入口。
2. 附上原始平面图，并提供已知尺寸。例如：

   > 使用 reconstruct-plan2world 重建这张原图。下方外墙长 600 cm。保留两次原始观察和程序审查结果，不要手改生成结果来改善展示。

3. Skill 先观察建筑和功能区，冻结观察后再观察家具；程序负责连接、门窗宿主、尺度、ID 和几何。不要反复重画局部结果来掩盖问题。
4. 在内部 authoring 工具接收 `plan2world-draft-v1`，对照原图检查尺度、墙、门窗、分区、露台边界和连通性，再保存原生 Project。程序通过不等于图纸还原正确。
5. 明确设置大门及朝内方向。建筑修正由内部编辑器完成；Godot 产品仅修改家具布置。
6. 用 **Arrange a Project…** 打开原生 Project；或从内部编辑器 **Export → Export runtime scene (.zip)** 导出，完整解压，再以 **Explore a scene…** 打开 runtime JSON。

此方式的 AI 请求由宿主执行和计费，不需要把宿主登录信息填入桌面工具。不要复制 ChatGPT 浏览器 Cookie、会话令牌或其他工具的认证文件。

## 用法二：独立桌面工具

### 1. 连接账户并选择模型

欢迎界面点击 **AI account…**。

- **Continue with OpenRouter** 在系统浏览器打开官方授权页。核对账户及预算后授权，经本机回调返回。工具不接收账户密码。
- 或在密码框输入自己的 OpenRouter API Key，点击 **Connect API key**。验证账户、读取模型列表不会发起付费推理。
- 手动选择一个支持图片输入和文本输出的模型，也可以填写准确模型 ID；模型还需支持本流程的 JSON 输出。工具不会自动选择付费模型。
- 界面显示 **该 Key 的累计使用额和预算剩余**，不是整个账户余额。未设置 Key 上限不代表免费或账户额度无限。
- 凭据只保留在本次进程内，**Disconnect** 或退出后清除，下次需重新连接。凭据不写入 Project、runtime ZIP、临时请求文件或日志。

Disconnect 只清除本机凭据，不撤销 OpenRouter 上的 Key。授权生成的 Key 需要撤销或改预算时，点击 **Manage OpenRouter keys…** 到提供方管理；重复浏览器授权可能生成新的 Key。

桌面版目前实现 OpenRouter。ChatGPT 账户可以使用上面的宿主 Skill 入口；桌面内的 Sign in with ChatGPT 尚未实现。OpenAI 已提供开源客户端官方方案，但需要独立完成身份校验、授权及流式请求接入，不能复用浏览器会话或将订阅当作普通 API Key。[官方接入文档](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)。

### 2. 准备图片并确认生成

在 **From an image** 选择原图。现成的平面图可直接使用；手机拍照可勾选 **Correct a photographed rectangle**，拖动纸张或已知矩形的四角，选择真实纸张比例或输入已知宽高比，点击 **Preview prepared image**，检查后选择 **Use prepared image**。**Rotate output 90°** 可调整最终方向；选中的角可用方向键微调，Shift 加大步长。

不要把户型外轮廓拉成矩形，也不要把不确定的纸张默认成 A4。保留尺寸标注；纸张宽高比不等于建筑实际尺寸。任意调整都会取消先前确认，准备过程在本机完成、不需要登录或 AI 额度。原图、变换和校正图均保留，Project 的背景使用校正图。

按需填已知建筑尺寸，再勾选使用自己 OpenRouter 额度发送两次观察，点击 **Reconstruct floor plan**。

确认后的图片发送到 OpenRouter 及所选模型服务商。两轮使用同一图片：第一轮观察建筑，第二轮携带冻结的建筑观察提取家具；共享程序随后完成像素辅助检查、逻辑闭合、门窗审查和 Project 组装。同次执行最多两次模型观察，前置审查失败时可能只发生一次。透视校正不额外调用模型。

**付费请求不会自动重试。** 取消、超时或无效结果仍可能产生费用；再次生成需重新确认。费用只显示提供方实际返回的值，未提供时不估算。观察与草稿在本机用户数据的 `creation-sessions/` 中保留供诊断，不是编辑撤销记录。原图不被修改。

### 3. 审查并明确选择大门

检查数量、假设和原图；图片编号只是程序投影回原图的已有门，并不代表已经确定哪扇是大门。

1. 点击门编号，或从列表选大门。
2. 选择墙方向左侧或右侧，使箭头指向室内。“左/右”指沿原生墙方向的两侧，不是屏幕固定左右。
3. **Save native Project…** 可先保存备份；指定入口后点击 **Open arrangement**。

入口过窄、出生点被阻挡或落在楼板洞上时，编译拒绝打开并保留之前的世界；不会猜门、移动出生点或填洞。可以重新选门和朝内方向。没有可靠门候选或建筑有误时，保存 Project 到内部编辑器修正，不为进入漫游凭空加门。

## 漫游与正交俯视

**F2** 切换同一个 Godot 世界中的第一人称和正交俯视，保留玩家位置、门状态及家具布局。切换过程暂停玩家输入；稳定的俯视使用正交投影，墙顶和地面没有透视偏移。

| 操作 | 正交俯视 / 布置 | 第一人称 |
| --- | --- | --- |
| 移动 | 中键或右键拖动平移，滚轮缩放 | WASD / 左摇杆；Ctrl 慢走、Shift 快走 |
| 观察 | 固定俯视，楼层选择器切换楼层 | 鼠标 / 右摇杆 |
| 家具 | 左键选中、拖动，释放接受合法位置 | 靠近后 F / 手柄 X 进入微调；方向键 / 左摇杆小幅移动 |
| 确认 / 取消 | Esc 取消当前拖动预览 | F / Enter / A 确认，Esc / B 取消 |
| 门 | 不走第一人称开门输入 | E 交互 |
| 菜单 | F1 暂停；菜单可回到编译出生点 | 同左 |

地面家具保持楼层高度；贴墙物品只在明确安装的墙面内移动。第一人称不能用鼠标大范围拖家具，也不自动吸附。窗口失焦会暂停并清除持续输入，需要明确恢复。

## 目录、吸附与保存

- **Tab / Items** 打开右侧分类、搜索和家具图块；Ctrl+F 搜索，Esc / 手柄 B 关闭。图块为已有家具图示，并非真实模型缩略渲染。
- **Place in room…** 先显示跟随鼠标的占地预览，绿色可放、红色受阻；点击确认后才加入工程。Esc、切层或失焦取消，不留下未接受的家具。替换家具也先预览再确认。
- 选中家具后显示 **Rotate / R**、**Swap / X**、**Remove / Delete**。替换需单独确认并保留 ID。
- 贴墙家具需明确选择墙、墙侧和底部高度；取消不修改 Project。曲墙挂装、新模型文件导入尚未提供，已有 Project 模型可使用。
- 安装对话框也可选 **Pick wall / ceiling in plan**，在平面图中点选明确的墙或顶面；墙侧和高度仍由你确认。目录和选中卡片中的 **placeholder** 表示占位物，需主动选择模型替换，不会按语义自动猜型号。
- **Align** 控制吸附，**Grid 10 cm** 控制网格；拖动按住 Alt 释放。支持直墙贴齐、朝向和邻近家具对齐。
- 摆放不能穿墙、占用门叶关闭体积或落在没有楼板支撑的位置；门当前打开也不能占用其关闭位置。
- **Layout… → Save layout… / Ctrl+S** 保存原生 Project；**Export scene…** 导出 runtime ZIP。**没有撤销、重做、操作记录**，删除或替换前自行保存文件备份。

### 平面图显示、吸顶灯和自然光

俯视采用不受光照影响的平面图配色：深色墙轮廓、橙色门位、蓝色窗位；关闭三维阴影和环境遮蔽。仍然使用同一个 Godot 世界和真实碰撞，切回漫游恢复材质和光照。旧 runtime 场景需要重新导出，才能得到编译器生成的门窗标记。

左上角的 **Furniture / Ceiling lights** 分别编辑普通家具和吸顶灯。吸顶层只显示、选择该层灯具，普通家具的碰撞仍然保留。当前支持吸顶灯、筒灯、吊灯和枝形吊灯四类；添加时明确选择支撑它的顶面。高度自动跟随该原生顶面，不能悬空、落地、跨孔洞或移出绑定区域。无顶、露天、倾斜/高低不一的顶面不会被自动补成平顶。

俯视拖动或漫游中 F / 手柄 X 选中后，灯具只沿顶面水平移动；漫游仍用方向键 / 左摇杆微调，不能用鼠标拖动。吸顶层可用 10 cm 网格，不会自动改绑附近的墙或其他房间。

选中灯具后点击 **Light… / L**，或在漫游中对准灯具按 **L**，可调整开关、流明亮度及色温。2700 K 偏暖，6500 K 偏冷。打开设置会取消尚未确认的移动；确认后保存当前灯具属性，取消不修改。灯具实际照亮场景表面，不只是模型自身发亮。

漫游右上角可选择 **Day / Night / Sunrise / Sunset**（白天 / 夜晚 / 日出 / 日落），也可以用 **T** 循环切换。先按 Esc 释放鼠标即可点击选择器。这些是展示预设，不是按地址和日期计算的太阳模拟。自然光模式是本次会话设置；灯具位置、顶面绑定、开关、亮度、色温会随 Project 保存和 runtime 导出。切换俯视不会改变这些灯具属性，也不会在俯视中显示受光差异。

### 已有门的门叶配置

俯视左侧 **Doors…** 可配置已有滑门/pocket 的固定扇、轨道、宽度与带符号行程，或双开/French 的首叶宽度比例。先选起始配置，再检查每叶参数并应用；取消不修改工程。门洞与宿主墙仍在内部建筑编辑器修改。

所有长度用厘米。关闭中心和正行程沿宿主墙 A→B，正轨道偏移朝墙左侧。固定扇行程为 0；平移扇行程可正可负。轨道或行程冲突会被真实物理阻挡，应用时不会自动猜测或修补。旧工程保持原单叶滑门/等宽双开默认；需要多轨时明确配置后保存。

| 文件 | 用途 |
| --- | --- |
| 原生 Project JSON / Project package | 主要保存格式，包含家具坐标、旋转、资产和固定建筑，可继续布置 |
| runtime scene ZIP | JSON 语义/碰撞 + architecture.glb + 模型资产，用于交付漫游；不能代替完整作者工程 |
| architecture.glb | 编译生成的静态建筑展示，不作为碰撞或编辑数据依据 |

## 常见问题与范围

**401 / 403**：检查 Key、权限或重新授权。失败的新连接不会替换当前账户。**402 / 429**：检查余额、Key 预算或速率限制；重新登录不能恢复额度，避免连续生成试错。

**墙、门窗或连通性错误**：回到原图与观察审查，Godot 不自动补墙补门。**家具只是方块**：可能是语义标记或缺少模型，可以替换，碰撞始终由编译器独立决定。

**需要改建筑**：使用内部 authoring 工具。桌面版只编辑室内布置，复杂楼梯和特殊门型仍按明确支持范围处理。

**误操作恢复**：只可取消当前预览；已接受的编辑通过已有文件备份恢复。

账户 GUI 和独立作者进程负责可选的在线生成；场景加载、物理和交互只消费编译产物。自动测试覆盖登录流程、PKCE、取消、共享组装、入口、正交拾取、编辑和保存，但账户/推理使用模拟提供方，不代表真实账户授权或外部模型质量验收。系统浏览器、实际授权、显卡、DPI、原生文件对话框和物理手柄仍需实机验收。
