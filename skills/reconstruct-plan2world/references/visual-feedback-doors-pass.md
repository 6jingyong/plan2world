# Optional door-geometry conflict reinspection

This explicit scope adds compiler-owned closed-leaf and sampled-motion questions.
These are questions about the CURRENT interpretation, not proof that an observed
door or wall is wrong. Inspect the same overview and original-pixel crops for
jambs, aperture extent, leaf/panel cues and adjoining boundaries. Wall thickness,
default hinge/swing side or an incomplete motion representation may explain a
collision even when the observed aperture is correct.

Use the ordinary decision envelope and only the pinned local architectural
records. Furniture, scale, functional seeds and native motion parameters remain
outside this scope. Do not shrink a door, remove a visible boundary, switch door
operation or move a wall merely to eliminate a collision. Record source-supported
alternatives; select null when the source or current contract cannot resolve it.
Unknown is preferable to disguising a mechanical limitation as a visual error.

Each candidate is reprojected and checked against compiler primitives. New
source-owned door/blocker conflicts, incomplete checks or unmapped ownership
prevent automatic application, while retaining the candidate and original. A
clean sampled check is not a real-engine opening or walkthrough acceptance.
